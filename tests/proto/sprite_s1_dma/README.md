## Exécution

1. Snapshot WinUAE, AGA PAL, 68030, **JIT OFF pour ce diagnostic**, mode fenêtré et timing chipset cycle-exact si disponible. Relever version WinUAE/configuration. Banque 29 libre. Les deux fichiers dans le même dossier. Project -> Merge ASCII dans un programme vierge, Runtime.
2. Le programme s'arrête sur un écran AMOS avec deux commandes **déjà calculées**, à noter ou photographier. Ne pas reprendre les adresses P2b : allocation dynamique. Shift+F12, entrer la première commande affichée (`w 0 $... 1 W CPU`), puis `w` pour contrôler le watchpoint et `g`. Revenir à AMOS et presser une touche.
3. **Arrêt Memwatch 0, valeur 01 :** Sprite visible après 100 déplacements. Entrer la seconde commande affichée (`w 1 $... $F8 RW DMA`), contrôler avec `w`, puis `g`. Doit se produire un arrêt Memwatch 1 causé par une lecture Sprite dans l'image (adresse dans IMAGE..IMAGE+71, canal 2, registre SPR2). Sauvegarder le message. Sans contrôle positif, l'absence de lecture ultérieure est INCONCLUSIVE. Si besoin vérifier l'aide `?` et la prise en charge de DMA par `v ?` selon version. Au contrôle positif, `w 1` supprime le watchpoint DMA, puis `g` reprend la séquence. Ne pas supprimer le watchpoint 0.
4. **Arrêt Memwatch 0, valeur 02 :** écran fermé, AMOS revenu, FreeSprite 2/3, trois WaitTOF déjà écoulés. Pour le relevé Copper, capturer `c`, `o 1`, `o 2` (si les listes sont disponibles ; examiner les pointeurs SPRxPT en particulier). Réarmer exactement la seconde commande (`w 1 $... $F8 RW DMA`), vérifier avec `w`, puis `g`.
5. **Arrêt attendu Memwatch 0, valeur 03**, après 300 WaitTOF additionnels, SANS arrêt Memwatch 1 intermédiaire. Tout arrêt 1 entre 02 et 03 est une preuve d'accès DMA tardif : conserver adresse, type, canal et registre ; supprimer 1 pour terminer sans libération. Capturer à nouveau les états Copper si disponibles. Supprimer `w 1`, puis `w 0` et `g`. Récupérer le journal et la transcription/captures du débogueur. Restaurer le snapshot, même en cas d'erreur.

## Verdict

Log `RAM:M19_S1P2C_DMA_RUNTIME.TXT` attendu : SOURCE_ERASED 1, PALETTE_OK 1, MOVES 100, BLANK_SET 1, BLANK_VBL 150, FREES 2, CLOSE_RETURNED 1, MARKERS 3, POST_WAITTOF 300, CHIP_HELD 248, DMA_FREE_PROVEN 0, RESULT 1, ERR 0, VERDICT PASS_DMA_OBSERVATION_SEQUENCE_ONLY. Ce verdict AMOS confirme uniquement la séquence du programme : il ne sait pas si le débogueur a réellement été armé. Il faut joindre la preuve positive Memwatch 1 sur le Sprite et les arrêts 02/03 avec surveillance DMA active. Une absence d'accès dans cette fenêtre est un résultat expérimental limité à cette configuration ; elle ne prouve ni l'absence de références dans toutes les listes Copper inactives, ni la sécurité de FreeVec pour tous les changements de ViewPort, réouvertures, erreurs, interruptions ou matériel. Ne pas lever DMA_FREE_PROVEN ni intégrer une libération native sur ce seul résultat.

Le bloc P2b de 244 octets garde son agencement, prolongé de 4 octets pour le marqueur CPU (un seul octet écrit à +244). Les deux watchpoints sont distincts : CPU W sur le marqueur, DMA RW sur les 248 octets. Aucune écriture directe des registres chipset ; aucune libération après exposition à GetSprite, quel que soit le résultat. L'outil externe est nécessaire car un compteur VBL ou SimpleSprite.posctldata ne démontre pas les accès DMA réels. La version locale de WinUAE n'est pas encore connue ; si le filtre DMA ou le marqueur ne fonctionne pas, classer INCONCLUSIVE, pas PASS. Les adresses du bloc et les mesures Chip/Fast sont journalisées. Pas de changement de Lib, token, ASM, Gate C ou D.
