**Diagnostic ajouté le 13/11/2026 après le deuxième échec WinUAE R63 :** la capture affichait `FICHIP 11 FLAGS 0`, toutes les valeurs BLIT/BCLP à 0, `RESULT 0`, `CHIP 1 796 472 / 1 796 472`. La nouvelle version du **même** ASC mesure `LOAD11 CHIP DELTA` et `LOAD11 FAST DELTA` **strictement autour du `Load` de la banque 11**, et affiche son `BANK 11 START`. Cela vise à déterminer si le cache est réellement en Chip. **Ne pas bypasser `TypeOfMem(MEMF_CHIP)`** ; même avec des flags natifs à 0, le Blitter ne doit pas lire de la Fast RAM. Le `RESULT 0` reste attendu tant que la cause n'est pas corrigée. Aucun nouvel exécutable Compiler demandé.

**Placement Chip obligatoire — correctif du protocole d'essai (13/11/2026) :** AMOS `Load` seul ne garantit pas une mémoire DMA-accessible, même si le fichier ABK annonce une préférence Chip. Le **même ASC** exécute désormais `Bank Permanent 11` puis `Bank To Chip 11` (commandes AMCAF) **après le Load**, avant toute commande `Aga F Blit`. L'adresse `Start(11)` peut changer. Le diagnostic conserve la valeur des flags natifs **avant/après** et le coût Chip/Fast cumulé du Load et du déplacement. **AMCAF doit être installée.** Le binaire natif R63 et la protection `TypeOfMem(MEMF_CHIP)` restent inchangés. Le précédent `RESULT 0` de R63 ne validait pas le placement du cache ; l'essai corrigé reste à faire **en interprété**, sans compilation.

**Test interprété :** installer R63 dans AMOS, redémarrer, mettre les deux ABK dans le dossier de travail, importer l'ASC dans un programme vide avec Project → Merge ASCII. **Load écrase les banques 10 et 11**, donc session WinUAE jetable. Exécuter en **interprété seulement** pour cette étape. Le bandeau n'affirme plus de compilation. Le test lit sans modifier le mot natif `Deek(Start(11)-12)` et affiche **`FICHIP 11 FLAGS`** : noter cette valeur pour confirmer ou écarter l'hypothèse des flags normalisés.

**Attendu avec le harnais corrigé :** `RESULT 1`, `CLOSE -1`, `NOS 0`, `SWAP 1` ; `CHIP PRELOAD/END` identiques (avant les deux `Load` et après les deux `Erase`), tandis que `CHIP CACHE ACTIVE` est inférieur d'environ 1 192 octets. L'ancien contrôle `_CF0<>_CF1` était incorrect. `ICON`, `BLIT`, `SHIFT`, `CLIP`, `OUT` doivent tous renvoyer 1 et `BAD` / `BCBAD` 0. Vérifier les icônes CPU et Blitter à l'écran ainsi que le clipping. Le code utilise un cache **préparé hors AMOS**, sans mesure du staging Fast→Chip.
