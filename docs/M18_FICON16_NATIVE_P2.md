# M18/P2 — noyau natif Fast Icon 16×16 AGA 8 plans (chemin aligné)

**Prototype interne 68000** : [émetteur natif](../tools/m18_ficon16_native_aligned_emit.py), [test CPU réel Unicorn](../tools/test_m18_ficon16_native_aligned.py). Source : [contrat P1 du format Unity](M18_FICON16_SOURCE_P1.md).

## Périmètre réellement codé

Le noyau reçoit **un slot déjà validé de 288 octets** : 16 lignes de 1 mot de masque préservation + 8 mots planaires (8 bitplanes, 256 couleurs). Il lit la source au CPU depuis **Fast ou Chip**, écrit les mots directement dans les 8 bitplanes Chip du back buffer **déjà validé par l'appelant**, sans Blitter, allocation, compression, Swap, attente VBL, palette ni écriture du front. Modes 0 opaque (couleur zéro visible) et 1 masqué (couleur zéro transparente selon les mots de masque Unity). Y est pixel-exact avec clipping, X est pixel-exact **seulement si déjà multiple de 16**, sinon retour 0 sans écriture ; **aucun arrondi silencieux**. Les mots voisins au bord droit sont protégés via un masque de dernier mot.

**ABI interne, PAS une signature AMOS :** A0 pointe vers 288 octets de source, A1 vers une table de 8 pointeurs Chip; D0=X, D1=Y, D2=BytesPerRow, D3=mode 0/1, D4=largeur écran, D5=hauteur écran. Retour D3=1 succès/no-op ou 0 rejet, D2=0. Sauvegarde des registres AMOS habituels, pile équilibrée, A3 intact. Une future enveloppe publique devra valider la banque AMOS existante, la taille, les masques canoniques, les 8 pointeurs, la propriété du buffer inactif et le Safe non bloquant **avant de transmettre la source au noyau**.

**P2 ajouté — staging réel CPU Fast→Chip :** [émetteur 68000](../tools/m18_ficon16_native_stage_emit.py), [test Unicorn](../tools/test_m18_ficon16_native_stage.py). Entrée A0=source icon Unity 288 octets, A1=cache Chip privé 288 octets, tous deux alignés et sans chevauchement. Le noyau transforme les 16 lignes intercalées (masque + 8 mots de plans) en un bloc plan par plan : **masque de visibilité 32 octets (complément du masque Unity de préservation), puis 8 plans de 32 octets**. La conversion masque est nécessaire : Unity code 1 = transparent/à préserver ; `BltMaskBitMapRastPort` attend 1 = pixel à remplacer. C'est un format de cache Chip préparatoire, pas encore un appel DMA. L'API d'AmigaOS documente une source masquée avec un masque binaire en Chip et un minterm de copie à travers le masque (`$E0`) ; l'appel effectif, les RastPorts et les attentes DMA ne sont pas implémentés dans ce P2. Il ne fait **aucune allocation**, n'a pas d'appel Blitter/AMOS, ne vérifie pas la nature Fast/Chip des adresses et refuse les zones source/destination chevauchantes ou non alignées. **Pas de mesure de vitesse ni de cache persistant prouvée** à ce stade.

**P3 complémentaire :** le [noyau CPU X quelconque pixel-exact](M18_FICON16_NATIVE_P3.md) est maintenant **Gate A PASS**, y compris les X négatifs et décalés de 1 à 15 ; il n'est pas encore raccordé à un token AMOS.

**Non encore implémenté :** wrapper AP20, lecture banque par numéro/ID via Bnk.GetAdr, allocation/gestion de cache Chip, backend Blitter masqué, double-buffer avec cache indépendant, allocation/libération et chronométrage WinUAE. Il s'agit d'une **première primitive du futur Fast Icon natif**, et **pas de R61 installable**.

## Validation

Le test CPU vérifie dans Unicorn M68000 les sorties sur quatre icônes à masque varié, plusieurs positions alignées avec clipping, modes opaque et masqué, comparaison octet pour octet des 8 bitplanes avec le modèle indépendant P1, mémoire sentinelle, source immuable, pile/ABI et rejets avant toute écriture. Les scénarios CPU natifs de dessin aligné et de staging, incluant l'inversion de masque, disposent d'une Gate A ciblée PASS sous Unicorn. Le wrapper AMOS/buffers/Safe et le Blitter matériel ne sont pas encore validés.

**États distincts :** contrôle statique/emission en environnement local, Gate A du noyau **dessin aligné PASS** sur [CI Artifact integrity du 13/11/2026](https://github.com/anthea176/AMOSPro-AGA-Extension/actions/runs/43394674903). Gate A du premier staging 288 octets **PASS** sur [CI 43395235674](https://github.com/anthea176/AMOSPro-AGA-Extension/actions/runs/43395235674), après correction de la pile du banc Unicorn. La **version corrigée qui inverse le masque Unity** obtient également **Gate A PASS** à l'étape staging de [CI 43395566726](https://github.com/anthea176/AMOSPro-AGA-Extension/actions/runs/43395566726). Ce PASS est une validation CPU sous Unicorn, non une exécution DMA ni une Gate C WinUAE, Gates B interprété et C compilé WinUAE **non effectuées**, Gate D Amiga physique **non effectuée**. Aucun test de débit réel ou comparaison CPU/Blitter autorisé à ce stade.

**Protection :** R60 0.13.5 LAST_GOOD, `dist/AMOSPro_AGA.Lib`, les ASC historiques et `tests/current/` restent inchangés. Aucun nouveau token, aucun R61, aucune branche.
