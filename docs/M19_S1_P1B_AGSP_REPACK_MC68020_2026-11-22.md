# S1-P1b — Repack AGSP v1 multi-images MC68020

**Date :** 22 novembre 2026. **Statut : source native et banc Gate A à exécuter.** [ASM de repack](../src/native/m19_s1/M19_S1P1B_AGSP_REPACK_MC68020.s) / [test CPU](../tools/test_m19_s1p1b_agsp_repack.py) / [CI combinée avec le pont RGB24](../.github/workflows/m19-s1-p1b-screen-rgb24.yml).

Le module **n'est pas** un éditeur de banque AMOS connecté à l'AP20. Il ne fait aucune allocation/transaction OS, `Bnk.GetAdr`, `Lst.Cree`, `Bnk.Change`, `Lst.Del` ou `Save/Load`. Il prend une image de capture AGSP 16px/2bpp préparée et un ancien **payload AGSP v1 éventuellement vide**, puis produit le **nouveau payload AGSP complet dans une allocation temporaire indépendante**. On ne remplace pas la banque AMOS avant les contrôles et sa publication native ultérieure.

## Format d'entrée (requête de 40 octets, A0)

| Offset | Type | Valeur |
| ---: | --- | --- |
| +0 | LONG | Ancien payload AGSP, `0` pour une banque neuve |
| +4 | LONG | Longueur de l'ancien payload, `0` pour une banque neuve |
| +8 | LONG | Image planaire 2bpp fraîche, **4×H octets** |
| +12 | LONG | Palette locale RGB24 de **48 octets** |
| +16 | LONG | Destination temporaire (buffer entièrement alloué) |
| +20 | LONG | Capacité de destination, **≤16 Mio** |
| +24 | WORD | `Id` image 1..4096 |
| +26 | WORD | `H` hauteur de capture 1..256 ; largeur fixée à 16 |
| +28 | WORD | Nombre de couleurs opaques, **0..3** |
| +30 | WORD | Indice transparent source, 0..255 |
| +32/+34 | WORD signé | Hotspot X/Y |
| +36 | LONG | Réservé 0 |

**Retour :** `D0=longueur`, `D1=1` succès ou `D0=D1=0` refus. Préserve `D2..D7, A2..A6`. Les allocations et leurs plages **doivent avoir été prouvées par l'appelant** ; ce noyau n'a pas de `Exec.TypeOfMem`. Le payload d'entrée, les pixels source et la palette source restent intacts.

## Algorithme

1. Vérifie la géométrie, les arguments et la capacité. Si ancien AGSP, vérifie version, magic, taille, entrée 48, IDs strictement triés et non dupliqués, dimensions, profondeur, stride, offsets pixels/palette contigus, réserves et génération. **Limite :** ne parcourt pas les indices de chaque pixel ni les 16 triplets RGB24 des anciennes images ; un validateur complet reste requis **avant la publication dans la liste AMOS**.
2. Calcule le **nombre d'images** après ajout/remplacement, le nouveau répertoire de 48 octets/entrée et la taille totale, en tenant compte des bytes d'images préservées. Rejet avant écriture en cas d'overflow, de manque de capacité ou d'ID hors plage.
3. Construit l'en-tête AGSP v1 (32 octets) avec **génération +1** ; reconstruit les entrées par ID croissant ; copie les anciennes images planaires + palettes byte-exactes et remappe leurs offsets.
4. Insère ou remplace l'image capturée. Pour elle, crée une entrée 16px/2bpp et copie pixels 4×H puis palette RGB24 48 octets dans le stage ; aucune palette matérielle AGA n'est modifiée.
5. Vérifie que le pointeur final correspond à la taille calculée. Une erreur ne doit **jamais** entraîner un remplacement partiel de la banque AMOS.

**Limite de sécurité :** aucune écriture avant validation structurale et calcul de capacité ; si une erreur impossible de cohérence de copie survient tardivement, le tampon **détaché** est à jeter. Le stage ne doit pas recouvrir l'ancien payload ni les buffers source : responsabilité du wrapper d'allocation/propriété.

## Contrôle

La CI assemble le source Motorola `-m68020`, puis exécute le **vrai binaire** via Unicorn MC68020 et compare ses sorties octet pour octet au modèle indépendant [AGSP v1](../tools/m19_s1_agsp_bank.py), avec :
- banque neuve ;
- insertions triées au début, au milieu et à la fin ;
- remplacement et conservation d'autres images ;
- conservation d'une ancienne image préparée en **S2/4 plans** ;
- limite de hauteur 256, valeurs RGB24 et transparence ;
- capacité insuffisante ; données corrompues ; refus sans écritures dans le stage, registres et canaries.

## Prochain point réel

Le code natif de **publication d'une banque AMOS DATA** (`Lst.Cree` → copie du payload stage → revalidation → écriture du lien → `Bnk.Change` → `Lst.Del`) doit être adapté **au format AGSP**, avec possession mémoire, revalidation de la liste et préflight complet des pixels. Le précédent P1e/AGBO est une source d'architecture, **pas un module AGSP déjà raccordé**.

Le test dans AMOS sur WinUAE devra utiliser `Get AGA Sprite` puis `Save` et `Load` et vérifier les tailles, images et palettes en Runtime **B** puis Compiler **C**. **Pas de nouveau binaire installable ni test WinUAE dans ce jalon.** Sprites DMA et palette matérielle : hors P1b.
