# AMOSPro AGA Extension 0.14.1 — Stability & Bug Fixes

> **DRAFT — 24 November 2026. Not released.** Final fixes, identity and validation must be updated after L0–L5 closure.

Version 0.14.1 is a corrective update to 0.14.0, focusing on the stability of AGA graphics and the software Bob engine. No new public commands are planned: 100 commands/functions, 203 AP20 entries, unchanged P2d signatures and MC68020/68EC020 minimum CPU.

## Fixes implemented in P2d-L2

- **Aga Iff Load:** acquire the Safe reply before bitmap writes; return 0 without drawing when Safe is unavailable.
- **Aga Back Fill:** acquire Safe with up to three WaitTOF retries; no drawing if Safe remains unavailable. Existing instruction syntax and lack of numeric return unchanged.
- **First B8 Bob binding after Swap:** acquire an available Safe reply when the first root is not bound. READY/DIRTY and historical Swap implementation unchanged.
- **Build and regression tooling:** synchronize exact source and binary identities and distinguish the frozen public Bob example from the active focused test. Final CI qualification remains open.

Applications must continue checking function results and respecting double-buffering and Bob-update contracts. No zero-refusal guarantee.

## Installation

Requires AMOS Professional, AGA chipset and Motorola 68020 or better. Back up the installed library and configuration, replace AMOSPro_AGA.Lib in APSystem using the existing slot, save configuration and restart AMOS. Import ASC examples via Project / Merge ASCII. Only the five C2P commands require separately installed c2p.library v1.9; the Bob engine and Aga Iff To Chunky do not require it.

Hardware AGA Sprites are not included; planned next feature milestone: 0.15.0.
