# 0.14.0 — checklist de publication GitHub et Aminet

> **Brouillons préparés seulement.** L'auteur effectue lui-même le tag, la release GitHub, la fabrication de `AMOSProAGA.lha` et l'envoi Aminet.

## 1. Vérifier les octets AVANT de préparer l'archive

- [ ] `dist/AMOSPro_AGA.Lib` et `dist/AMOSPro_AGA_LAST_GOOD.Lib` sont **strictement identiques** : **136 020 octets**, SHA256 `ce5fb614c7acae9b1bb88e1d793d73dbe7ba747edc285acb7d9e72ac3104176f`, Git blob `8a849b89aae57c2cda0b4db8771034a0978d3e78`.
- [ ] `$VER:` interne = `AMOSPro_AGA M19 P2d` (ne pas modifier le binaire pour y ajouter 0.14.0 : cela changerait le SHA et l'identité de la Lib testée).
- [ ] La [CI documentation et la politique de livraison](https://github.com/anthea176/AMOSPro-AGA-Extension/actions) passent après promotion P1e → P2d. Les bancs statiques ne remplacent pas les deux preuves Runtime/Compiler déjà conservées.
- [ ] L'exemple public [`BOB_ALL_IN_ONE.asc`](../../examples/bob_p2_all_in_one/BOB_ALL_IN_ONE.asc) et le [test figé](../../tests/passed/M19_P2_ALL_IN_ONE.asc) ont le même blob `c48d334fd4508d402d28399bffdfec08d4cb4acb`.

## 2. Construire localement le paquet Aminet `AMOSProAGA.lha`

- [ ] Archiver **le véritable `AMOSPro_AGA.Lib` P2d validé**, les exemples (notamment `BOB_ALL_IN_ONE.asc`), les guides d'installation et documents pertinents, `LICENSE` et `ASSETS_LICENSE.md`.
- [ ] Exclure les `dist/experimental/` et anciens candidats ; ne pas transformer des `.asc` ASCII en `.amos` binaire ou en fichiers texte modifiés.
- [ ] Vérifier le contenu de l'archive avec un outil LhA adapté, extraire dans un répertoire de contrôle et revérifier le SHA de la Lib extraite. **Ne jamais simplement renommer un ZIP en LHA.**
- [ ] Conserver la notice [`AMOSProAGA.readme`](AMOSProAGA.readme) avec les en-têtes **Short, Author, Uploader, Type `dev/amos`, Version `0.14.0`, Architecture**, ASCII et fins de ligne CRLF. Vérifier que le `.readme` décrit exactement l'archive.
- [ ] Garder **le même nom d'archive** que l'upload précédent sur Aminet : `AMOSProAGA.lha` (remplacement/mise à jour de la même entrée `dev/amos`).

## 3. Publier soi-même sur GitHub

1. Ouvrir [Releases](https://github.com/anthea176/AMOSPro-AGA-Extension/releases) → **Draft a new release**.
2. **Create new tag** : `0.14.0`, cible **`main` après la promotion et les CI**. Ne pas réutiliser `0.13.27` et ne pas avancer un ancien tag.
3. Titre : `AMOSPro AGA Extension 0.14.0 — AGA Bob Engine`.
4. Coller les [notes GitHub préparées](0.14.0_GITHUB_RELEASE.md). Décocher **Pre-release** pour une version normale ; cocher **Latest release** si proposé.
5. Joindre le fichier **`AMOSProAGA.lha` contrôlé**, vérifier le nom, la taille et le contenu, puis **Publish release**.

## 4. Mettre à jour Aminet soi-même

1. Utiliser le circuit habituel d'upload Aminet, catégorie **`dev/amos`**.
2. Fournir **`AMOSProAGA.lha`** et **`AMOSProAGA.readme`**, même nom de base, version **0.14.0**.
3. Conserver l'auteur et l'uploader indiqués dans la notice fournie précédemment, sans inventer de nouvelle adresse.
4. Une fois indexé, vérifier la fiche et télécharger/extraire l'archive publiée pour confirmer le SHA **P2d**.
