# AMOSPro AGA Extension 0.14.0 — AGA Bob Engine (M19 P2d)

This release completes the **M19 software Bob engine (P0–P2)** for AMOS Professional on AGA-equipped Amiga systems. It is the next public release after **0.13.27**.

**Release identity:** M19 P2d — **100 native AMOS commands/functions**, **203 AP20 entries**, **68020/68EC020 minimum**. The exact tested `AMOSPro_AGA.Lib` binary (136,020 bytes, SHA256 `ce5fb614c7acae9b1bb88e1d793d73dbe7ba747edc285acb7d9e72ac3104176f`) is promoted to `LAST_GOOD` without rebuilding or modifying it. Its internal `$VER` string remains `AMOSPro_AGA M19 P2d`.

## What's new

- **Complete AGA Bob system** on a private indexed AGA screen: multi-image AGBO banks, positioning, masks/transparency, priority, hotspots and image selection; safe per-page background restoration, updates and resource cleanup.
- **P2a — `Aga Bob Col(A,B,Mode)`**: rectangle or opaque-pixel mask collisions.
- **P2b — `Aga Bob Flip(N,Mode)`**: normal, horizontal, vertical and combined flips.
- **P2c — `Aga Bob Planes(N,Mask)`**: select destination bitplanes when drawing Bobs.
- **P2d — `Aga Bob Auto Update(Mode)`**: optional automatic Bob update through the guarded `Aga Swap` path.
- **P2e — AMAL bridge**: two synchronous AMAL channels drive separate AGA Bobs using AMOS memory buffers, without introducing a new AMAL extension token.
- **[BOB ALL IN ONE example](https://github.com/anthea176/AMOSPro-AGA-Extension/tree/main/examples/bob_p2_all_in_one)**: self-contained ASCII source with asymmetric F/L graphics, animated Bobs, collisions, flips, plane masks, automatic updates and a diagnostic `RAM:` log.

The existing screen, palette, Copper, Blitter, IFF/ILBM, AGAPIC, font-bank, input, Fast Icon, CBlock and C2P functions remain part of the extension.

**Known synchronization behaviour:** in each run, **121 initial `Aga Swap` refusals were recovered after one extra VBL**. Do not interpret the final PASS as zero refusals or guaranteed real-time performance. **Physical AGA hardware (Gate D) and strict interpreted mode remain untested**. The test does not requalify every unrelated historical API.

## Installation

1. Requires **AMOS Professional**, an **AGA chipset**, and **MC68020/68EC020 or better** (A1200/A4000 or compatible WinUAE).
2. Back up the existing AMOS configuration and library. Install `AMOSPro_AGA.Lib` in the configured `APSystem` extension slot (historically slot **14**, only if free); save interpreter settings and restart AMOS.
3. Import example `.asc` sources through **Project → Merge ASCII** into an empty program. Read [INSTALL.md](https://github.com/anthea176/AMOSPro-AGA-Extension/blob/main/INSTALL.md) and the [example instructions](https://github.com/anthea176/AMOSPro-AGA-Extension/blob/main/examples/bob_p2_all_in_one/README.md).
4. **Only the five C2P commands** require a separate `c2p.library v1.9` in `LIBS:`; the Bob engine and `Aga Iff To Chunky` do not require this dependency.

## What's next?

**Hardware AGA Sprites (S0–S3)** are the next development milestone, **separate from software Bobs**. The existing [Sprite audit](https://github.com/anthea176/AMOSPro-AGA-Extension/blob/main/docs/AGA_HARDWARE_SPRITES_S0_AUDIT_2026-11-21.md) will be completed before implementing the first 16-pixel hardware Sprite. **No hardware Sprite API is included in 0.14.0.**
