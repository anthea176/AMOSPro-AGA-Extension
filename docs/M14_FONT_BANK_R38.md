# M14 / R38 v0.11.0 — AMCAF BankFont selection

**User-approved contract:** `_OK=Aga Font Bank Select(Start(bank),Length(bank))`.
This document describes the test **candidate**; R37 v0.10.9 remains WinUAE-PASS `LAST_GOOD` until R38 Gate B succeeds. R38 only adds one public AP20 command (44 commands total). Compiler Gate C and real AGA Gate D are not tested.

## AMCAF source reference

The user supplied a real `AMCAF_FONT9.abk` generated by AMCAF `Change Font "topaz.font",9` and `Make Bank Font 10` was inspected locally, but its Topaz ROM glyph data are **not redistributed in the public repository**. Gate A uses a deterministic original synthetic `BankFont` with identical structural offsets, created by `amcaf_font_r38_layout.synthetic_abk()`; Gate B uses the user-owned original file. Its 20-byte on-disk `AmBk` header indicates bank 10, a `BankFont` name and 2860-byte `FONT` payload (file 2880 bytes). In AMOS RAM, the native bank header is 24 bytes **before** `Start(10)`. `Length(10)` is the payload size; never add the on-disk AmBk header.

This sample is an AmigaOS `TextFont` image embedded at payload offset 24, with 1-bit strike bitmap at offset 106 and character-location table at offset 1960. At payload offsets +44/+48/+50 are `tf_YSize=9`, `tf_XSize=10`, baseline 6; at +56/+57 characters 32..255; modulo 206 at +62; table size is 225 * 4 bytes (including the fallback glyph). The saved absolute addresses (`ln_Name`, `tf_CharData`, `tf_CharLoc`, `tf_Extension`) are **not valid** after the bank is loaded elsewhere.

AMCAF V1.40 manual confirms `Make Bank Font bank` and `Change Bank Font bank` represent disk-independent graphical fonts; this is distinct from `Change Print Font`'s 2048-byte 8x8 bitmap bank (R39). AMCAF V1.31 fixed a historical Make Bank Font error; pre-V1.31 banks are not accepted as a guaranteed format.

## Public API and semantics

```amos
Load "RAM:AMCAF_FONT9.abk",10
_OK=Aga Font Bank Select(Start(10),Length(10))
Erase 10
_TX=Aga Text(24,72,1,"AMCAF BANK FONT")
```

- Function `Aga Font Bank Select(Start,Length)` returns integer 1 on success, 0 on refusal; both parameters numeric, AP20 signature `00,0`, latest length in D3 and previous Start pointer at `(A3)+`. Invalid requests leave the previous font unchanged. No work without the private AGA Intuition screen and graphics.library.
- Caller **must** pass a live, genuine AMOS bank `Start(bank)` and its matching `Length(bank)`. TypeOfMem on the AMOS header and final byte filters unmapped addresses but does **not** authenticate arbitrary pointers or guarantee their allocation provenance. Never pass stale or fabricated pointers.
- R38 preflights: aligned pointer, bounded length 112..65535, in-memory AMOS header length/number/type/name, `FONT` signature, size/offsets, `TextFont` metrics, bitmap stride/height, single-bit non-color font, non-proportional glyph table and every `CharLoc` entry. Bank data are never modified.
- On success R38 uses `AllocVec(MEMF_PUBLIC|MEMF_CHIP|MEMF_CLEAR)` and Exec `CopyMem`, patches the **private copy**'s `TextFont` pointers and reset attributes, then commits the selection. The saved absolute pointers are never dereferenced. `Erase bank` becomes safe immediately after successful selection.
- `Aga Text` continues to render only on the extension's AGA back buffer, using `SetFont` before `TextExtent`; R26/R27 bounds, Safe/Disp, transparent JAM1 and no implicit VBL are preserved. Native AMOS Text/Print and AMCAF `Change Bank Font` are not redirected.
- R37 diskfont and R38 bank fonts share one selection. The old R37 `CloseFont` call sites are replaced by a checked release helper: OS fonts use `CloseFont`, heap-owned bank fonts use `graphics.library/StripFont` (V36, LVO -822, A0) followed by `Exec/FreeVec`. Reset, switching and `Aga Screen Close` release the owner exactly once.
- **Initial scope:** monochrome BankFont with non-proportional, non-color `TextFont` (no `tf_CharSpace` or `tf_CharKern`). Other variants and malformed banks return 0; they are not converted silently. AMCAF `Change Print Font` banks (2048 bytes) remain for R39. No file IO and no dependency on AMCAF at runtime.
